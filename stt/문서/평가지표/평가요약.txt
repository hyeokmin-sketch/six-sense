SIX-SENSE STT 표준어 성능 평가 요약 (SenseVoice)
작성일: 2026-10-15
상세 보고서: SIX-SENSE_STT_표준어평가.md / 오인식 사전: stt_딕셔너리.xlsx, STT_오인식사전_LLM용_원본.json

==================================================================
1. 무엇을 했나
==================================================================
- 사투리가 아닌 표준어 문장으로 SenseVoice 자체 성능을 측정
  * 일반 문장 1,000개: 일상 대화, 질문, 감정 표현, 비서 명령(알람·날씨·문자·일정 등)
  * 프로젝트 문장 3,000개: 블라인드·에어컨·조명 명령(켜라/꺼라/줘/주세요 등), 상황+명령, 질문, 복합, 예약
- 문장마다 TTS 목소리 2개로 음성 생성 → 총 8,000개
  * SAPI : Windows 내장 Heami. 발음이 자연스러움 → STT 실력을 보는 기준
  * VITS : 기존 tts_a1 학습에 쓴 kss 목소리. 발음이 자주 뭉개져 참고용
- 모델 2개 비교: 원본(보드에 들어가는 int8 모델), tts_a1(경상도 파인튜닝)
- 지표
  * CER       : 글자 오류율(공백·문장부호 제외, 낮을수록 좋음). "이십육 도"와 "26도"는 둘 다 정답
  * 완전일치  : 한 글자도 안 틀린 문장 비율
  * 키워드    : 기기명 / 동작(켜·꺼·올려·제습…) / 숫자가 출력에 그대로 들어있는 비율

                      일반 1,000문장     프로젝트 3,000문장
  CER                     4.2%              5.2%
  완전일치               66.9%             56.0%
  기기명 인식              -               94.5%
  동작 인식                -               85.9%
  숫자 인식              99.1%             67.3%  (퍼센트 누락 때문, 아래 4번)
  처리 시간       문장당 약 0.2초 (이 PC CPU 8스레드)

  * VITS 목소리는 CER 약 20%. 대부분 TTS 발음 문제라 STT 성능으로 보지 않음

3. 결과 - 원본 vs tts_a1 (SAPI 목소리 기준 CER)
==================================================================
                      원본      tts_a1
  일반                4.2%      8.1%   ← 나빠짐
  프로젝트            5.2%      7.2%   ← 나빠짐
  숫자(프로젝트)     67.3%     86.6%   ← 좋아짐

  * tts_a1은 표준어에도 사투리 어미를 붙임
    "했어"→"했소", "있어"→"있소", "올려 줘"→"올려주소"
  * 표준어 사용자도 고려하면 원본 모델 + 오인식 사전 보정이 더 안전

4. 자주 틀리는 것 (원본 모델)
==================================================================
  [1] 꺼 → 거 (가장 중요)
      SAPI 음성에서 "꺼"가 든 문장 278개 중 274개가 "거"로 나옴
      예) "거 줘", "거라", "거 지게", "거졌어"
      ※ 켜↔꺼, 올려↔내려가 서로 뒤바뀐 경우는 6,000개 중 1건뿐

  [2] 줘 → 죠 / 져 / 쳐
      예) "켜 줘" → "켜 죠", "맞춰 줘" → "맞춰 져"

  [3] 된소리·거센소리 혼동 (기기·방 이름)
      블라인드→플라인드   안방→안팡     작은방→작은 빵   큰방→근방/금방
      형광등→현광등      밝기→발기     전구→전국/전고   틀어→들어
      서재→서제          부엌→부업     세기→색이       무드등→무드든

  [4] 숫자 변환 부작용
      "세게" → "3 개"
      "오십 퍼센트로" → "50 로" (퍼센트가 빠짐)
      → 블라인드·밝기 뒤에 "숫자+로/만"이 오면 퍼센트로 해석해야 함

  [5] 같은 말 반복 출력
      "저녁은"→"저녁녁은", "보내"→"보내 내", "뒤에"→"뒤에 에"

5. LLM 쪽 반영 제안
==================================================================
  - STT_오인식사전_LLM용_원본.json의 "치환표"를 프롬프트나 전처리에 넣기
    단, "문맥주의" 목록(거, 금방, 좀 등)은 정상 단어이기도 하므로 기기 명령 문맥에서만 바꾸기
  - 프롬프트에 규칙 명시
    "기기 명령에서 '거'는 '꺼(끄다)'", "블라인드/밝기 뒤 숫자+로는 퍼센트", "'3 개'는 '세게'"
  - LLM 학습 데이터에 STT 출력 그대로의 문장을 섞기
    (학습데이터/std/eval/원본_domain.csv 의 hyp 열)

6. 한계
==================================================================
  - 사람 목소리가 아니라 TTS 여성 목소리 2개. 실제 사람·소음·먼 마이크에서는 더 나쁠 것
  - "꺼→거"가 Heami 목소리 발음 탓인지 실제 녹음으로 확인 필요
  - 사전의 "바로 치환"은 평가 문장 안에서만 확인한 것. "모래(→모레)"처럼 일반 단어일 수 있음
  - 오븐 등 블라인드·에어컨·조명 외 기기는 이번 범위에 없음 (stt/std_sentences.py에 추가 후 재실행)
