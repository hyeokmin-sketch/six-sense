# SIX-SENSE LoRA 파인튜닝 버전별 요약 (v1 · v2 · v2dict · v2dict2)

작성: 2026.11.7 · 모델: Llama-3.2-1B-Instruct, Qwen3.5-2B · 방식: LoRA → 경상도 발화를 호출 형식(`<six_0>(object=1, type=1)<six_end>` 등)으로 변환

---

## 1. 한눈에 보기

| 버전 | 한 줄 요약 | 학습 데이터 | 바뀐 점 |
|---|---|---|---|
| **v1** | 첫 파인튜닝 | 2,915 (검증 327) | 템플릿으로 만든 1차 데이터 |
| **v2** | v1에서 틀린 유형 보강 | 3,497 (검증 400) | 복합·단일·되묻기 문장을 늘림 |
| **v2dict** | STT 오류 입력을 학습에 추가 | 4,391 | v2에 사전 적용 STT 오류 입력 894개 추가 |
| **v2dict2** | 해당 없음 보강 | 4,652 | v2dict에 "우리 기기가 아닌 말" 261개 추가 |

흐름은 이렇습니다. v1은 기본 학습이고, v2는 v1이 틀린 유형을 채웠고, v2dict는 STT가 글자를 잘못 적어도 맞히도록 가르쳤는데 그 과정에서 해당 없음 오작동이 늘었고, v2dict2는 그 부작용을 고쳤습니다.

---

## 2. 공통 학습 설정 (v2 이후 노트북 기준)

| 항목 | 값 |
|---|---|
| LoRA | r=16, alpha=32, dropout=0.05, 모든 선형층 |
| 학습 | 3 epoch, 학습률 2e-4(cosine), 배치 4 × 누적 4, fp16(T4), 최대 길이 192, seed 42 |
| 손실 | 정답(호출) 부분에만 적용 |
| 환경 | Google Colab, T4 GPU |
| 호출 형식 | 기기 3개(조명·에어컨·블라인드), 14종 동작 + 되묻기(`object=-1`) + 해당 없음(`<six_2>()`) |

## 3. 버전별 상세

### v1 — 첫 파인튜닝

- **데이터:** 학습 2,915 + 검증 327. 어휘·어미를 조합한 템플릿 생성 데이터(사람이 쓴 문장이 아님, 발표에서 "생성 데이터"로 명시).
- **구성:** 단일 1,647 · 복합 732 · 해당 없음 383 · 되묻기 153.
- **평가:** 대구 50대 평가 35문장.
- **결과:** Llama — 50대 71.4%, val 98.8% / Qwen — 50대 77.1%, val 99.7%.
- **의미:** 기본 틀은 학습됐지만 실제 화자 문장(50대 평가)에서는 70%대였습니다. 쉬운 val은 이미 98~99%여서, 문제는 **val이 아니라 새로운 화자의 문장**이라는 것을 보여 줬습니다.

### v2 — v1에서 틀린 유형 보강

- **데이터:** 학습 3,497 + 검증 400. v1보다 **595개 증가**.
- **구성:** 단일 1,899(+252) · **복합 1,044(+312)** · 해당 없음 383(변화 없음) · 되묻기 171(+18). 복합 문장이 가장 많이 늘었습니다.
- **평가:** 대구 50대 36문장, 20·30대 v3 89문장 등.
- **결과:** Llama — 50대 100%, val 99.5%, v3 97.8% / Qwen — 50대 100%, val 99.8%.
- **의미:** 50대 평가가 100%로 올랐습니다. 다만 이 평가는 문장이 36개로 작고 포화돼서, "해당 없음에 기기를 조작하는" 문제(오작동)나 STT 오류 입력은 따로 점검해야 했습니다. 해당 없음 오작동이 문제로 확인되어 중간발표의 "발견한 문제"가 됐습니다(Llama 24.1%, Qwen 13.8%).

### v2dict — STT 오류 입력 학습 추가 (중간 단계)

- **배경:** STT(SenseVoice)가 사투리를 틀리게 적는 것이 병목이라는 측정 결과(강한 사투리 명령 유지율 66.8%)가 나왔고, 치환 사전(106쌍)을 확정했습니다.
- **데이터:** v2 3,497 + **A 세트 894 = 4,391**. A 세트는 "TTS 음성을 STT에 넣어 얻은 글자 중, 사전을 적용한 뒤에도 틀렸지만 기기·동작 단어가 남은 입력 + 정답 호출"입니다.
- **A 세트의 특징:** 전부 명령 문장이고, **해당 없음 예시가 없습니다.** 그래서 학습 데이터에서 해당 없음 비율이 11.0%에서 8.7%로 떨어졌습니다.
- **결과:**
  - 사전 holdout(330): 이전 74.5% → **92.1%** (큰 폭 개선)
  - STT 오인식 평가(708): 84.9% → 87.7%
  - 50대 100%, val 99.0%
  - **해당 없음 50대검수: 7/29 → 10/29 (악화)**
- **의미:** STT 오류 입력에는 효과가 있었지만, 글자가 깨진 입력에서 명령을 찾아 실행하는 쪽으로 쏠려 **해당 없음 오작동이 늘었습니다.** 이 모델은 채택하지 않았습니다.

### v2dict2 — 해당 없음 보강

- **데이터:** v2dict 4,391 + **해당 없음 261 = 4,652.** 해당 없음 비율 13.8%로 회복.
- **새로 넣은 261개:**
  - 다른 물건 명령 131 — 가습기·컴퓨터·프린터, 가스렌지·촛불, 차 창문·시동, 핸드폰 화면, 커튼 등
  - 기기를 언급하지만 명령이 아닌 말 52 — 에어컨 전기세, 블라인드 먼지, 불조심해라 등
  - 일상 문장 39
  - STT 오류 형태로 바꾼 변형 39
  - 평가셋과 겹치는 문장은 제외했습니다.
- **결과 (Llama / Qwen):**
  - 해당 없음 50대검수 조작 오류: 1/29 / **0/29**
  - 학습에 쓰지 않은 물건 54문장: **0 / 0** 오작동
  - 사전 holdout: 91.5% / 90.6%
  - STT 오인식 평가: 85.0% / 85.7%
  - val: 99.5% / 99.8%, 50대: 97.2% / 100%
- **의미:** 해당 없음 오작동이 해소되었고, 사전 holdout 개선은 유지되었습니다. 대신 이전 STT 평가셋(eval_stt_aug)에서는 개선이 사라졌고 복합 명령이 소폭 약해졌습니다(아래 참고).

## 5. 해석

1. **학습 데이터의 균형이 결과를 좌우했습니다.** v2dict는 STT 오류 입력만 늘렸더니 해당 없음 오작동이 늘었고, v2dict2에서 해당 없음을 보강하자 풀렸습니다. 데이터 종류를 늘릴 때는 다른 종류의 비율이 깨지지 않는지 함께 봐야 합니다.
2. **val과 50대 평가로는 차이를 볼 수 없습니다.** 둘 다 99~100%로 포화돼 있어서, 모델을 가르는 평가는 해당 없음 오작동, STT 오인식, 사전 holdout입니다.
3. **사전과 A 세트는 효과가 있었지만 범위가 좁습니다.** 사전 holdout은 약 17%p 올랐지만, 다른 TTS로 만든 STT 오류(eval_stt_aug)에서는 85%대로 같았습니다.
4. **Llama와 Qwen은 정확도가 비슷하고 Llama가 가볍습니다.** Qwen은 파라미터가 1.5배, 추론이 약 2배 느립니다. 반면 Llama는 STT 오류가 섞인 해당 없음에서 조작 오류가 더 적었습니다(1/83 대 5/83). 보드 양자화 후 비교가 필요합니다.

## 6. 한계와 주의

- **작은 평가셋:** 50대 36, 해당 없음 29, 신규 물건 54문장은 몇 문장 차이가 우연일 수 있습니다.
- **일부 평가의 낙관:** 해당 없음 29문장은 같은 종류의 물건을 학습에 넣어서 점수가 좋게 나왔을 수 있고, 사전 holdout은 A 세트와 같은 TTS·문장 집합이라 실제 음성보다 낙관적입니다. 신규 물건 평가는 학습에 쓰지 않은 물건으로 만들었지만, 학습 보강 데이터와 같은 방식으로 제가 만든 문장입니다.
- **이전 노트북의 4/29는 Qwen 값으로 보입니다:** 옛 노트북 출력의 해당 없음 50대검수 4/29(13.8%)는 Qwen의 기존 수치(13.8%)와 같고, Llama v2의 재측정 7/29(24.1%)는 기존에 알려진 Llama 수치(24.1%)와 같습니다. 즉 같은 Llama 어댑터에서 값이 달라진 것이 아니라, 옛 출력이 다른 모델 실행의 결과였을 가능성이 큽니다.
- **복합 명령 약화:** eval_stt_aug 복합 문장이 v2 161개에서 v2dict2 153개로 줄었습니다.
- **TTS 음성 기반:** STT 평가는 TTS가 만든 음성이라 실제 사람 목소리보다 쉽게 나올 수 있습니다. 실제 50대 녹음 STT 결과로 다시 확인해야 합니다.
- **형식 오류 방어:** Qwen이 존재하지 않는 기기(`object=4`)를 출력한 사례가 있어, 파서가 정의되지 않은 호출을 무시하거나 되묻기로 처리해야 합니다.
- **미측정:** 보드 위 양자화(RKLLM W8A8) 후 성능, 실제 사람 음성 종단 평가.
