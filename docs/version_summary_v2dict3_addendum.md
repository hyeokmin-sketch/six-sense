## 3. B 세트란? (쉬운 설명)

TTS 음성 3,840개를 STT에 넣어서 얻은 글자 중, **치환 사전을 적용한 뒤에도 틀린 것**을 학습용 후보로 모았습니다. 이 후보를 두 가지로 나눴습니다.

| | A 세트 | B 세트 |
|---|---|---|
| 기준 | 글자는 틀렸지만 **기기와 동작 단어가 남아 있음** | 기기 또는 **동작 단어가 사라짐** |
| 개수 | 894 | 336 |
| 처음 판단 | 학습에 사용 | **학습에서 제외** (정답을 추측해야 해서) |
| v2dict3 | 그대로 사용 | **기기 단어가 남은 279개를 추가** |

B 세트 336개는 다시 둘로 나뉩니다.

| 종류 | 개수 | 예시 (원래 말 → STT가 적은 글자) | v2dict3 |
|---|---|---|---|
| **동작 단어만 사라짐** (기기는 남음) | 279 | `에어컨 마 꺼 주소` → `에어컨 바꿔 주소.` <br> `방에 불 빨리 꺼삐라` → `방에 불빨리 꺾라.` <br> `블라인드 내리 주이소` → `블라인드 네리주의소.` <br> `에아컨 언능 꺼 도고` → `에어컨 얻는 거 도구.` | **추가** |
| **기기 단어까지 사라짐** | 57 | `에어콘 온도 올려 주소` → `에어콘 올려 주소.` <br> `아 불을 언능 켜 주이소` → `아 부을 언켜주소.` | 제외 유지 |

A 세트의 예시는 이렇습니다: `전깃불 얼른 켜 주이소` → `전깃불 얼른 켜 주소.`, `온도를 함 내리래이` → `온도를 한 내리래이.` 처럼 **글자는 조금 달라도 기기와 동작이 읽히는 경우**입니다.

**한 줄로:** A는 "조금 틀렸지만 읽을 수 있는 입력", B는 "핵심 단어가 깨져서 정답을 알기 어려운 입력"입니다. 이번에 B 중 기기 단어는 남아 있는 279개를 학습에 넣었습니다.

## 4. 왜 B 세트를 넣었나

**① 실제 녹음에서 가장 위험한 오류가 B 세트의 패턴이었습니다.**
v2dict2의 실제 녹음 오답 12개 중 **6개가 켜기↔끄기 뒤집힘**이었고, 모두 끄기 문장이었습니다. STT가 `끄`를 `그 / 으 / 끌`로 적으면 모델이 켜기로 답했습니다.

| 원래 말 | STT 글자 | v2dict2 출력 |
|---|---|---|
| 형광등을 끄라 | 형광등을 끌어라. | 조명 켜기 |
| 조명을 끄래이 | 조명을 그래. | 조명 켜기 |
| 형광등 좀 끄 주이소 | 형광등 좀 그 주소. | 조명 켜기 |
| 에어콘 고마 끄라 | 에어컨 고마 으라. | 에어컨 켜기 |

**② B 세트 안에 이 패턴이 많은데 학습에서 빠져 있었습니다.**
- 기기 단어가 남은 B 279개 중 **끄기가 123개(44%)** (에어컨 끄기 62 + 조명 끄기 61)
- `그 주`가 들어간 B 문장 18개는 **전부 끄기**
- 즉 모델은 "기기 + 깨진 동작"을 거의 본 적이 없어서 어느 쪽인지 모를 때 켜기로 쏠렸다고 판단했습니다.

**③ 공정성은 유지했습니다.** 이 279개는 TTS에서 나온 데이터이고, 실제 녹음 95문장은 처음부터 학습에서 제외한 평가 전용 데이터입니다.

## 7. 해석과 주의

1. **B 세트 추가는 의도한 효과가 있었습니다.** 끄 계열 STT 오류에서 켜기로 답하던 문제가 크게 줄었고, 복합 명령도 함께 좋아졌습니다 (예상하지 못한 효과).
2. **해당 없음 오작동은 대체로 안정적입니다.** 50대검수 0/29, 신규 물건 0/54. 다만 STT 오인식 평가셋에서는 1/83에서 3/83으로 조금 늘었습니다 (`오늘 온 요 이이고` → 온도↑, `선 풍게 바람 쎄게 해라` → 바람↑). 동작이 깨진 입력을 학습한 만큼, 글자가 깨진 해당 없음 입력에서 약간 추측하는 경향이 생긴 것으로 보입니다.
3. **사전의 효과가 LLM 정확도에서는 사라졌습니다.** 실제 녹음에서 사전 적용과 미적용이 같은 94.7%입니다. 이제 LLM이 사전이 하던 일을 대신 하는 부분이 큽니다. 사전은 CER을 낮추는 효과는 있으므로 그대로 둡니다.
4. **사전 holdout 98.2%는 낙관적인 값입니다.** 학습과 같은 TTS·문장 집합에서 나온 평가입니다.
5. **실제 녹음 94.7%는 완전히 깨끗한 점수가 아닙니다.** 95문장 자체는 학습에 쓰지 않았지만, 이 문장의 오류를 보고 B 세트를 넣기로 결정했기 때문입니다. 정확도를 대외적으로 말하려면 새로 녹음한 문장으로 한 번 더 평가하는 것이 가장 정직합니다.
6. **평가셋이 작습니다.** 95문장에서 몇 문장 차이는 우연일 수 있습니다.
7. **B 세트 처리 방식은 팀 합의가 필요합니다.** (아래 8장 참고)
8. **미측정:** 보드 위 양자화(RKLLM W8A8) 후 성능, 새로 녹음한 문장에서의 평가, Qwen v2dict3.

## 8. B 세트 처리 방식 — 팀 합의가 필요한 이유

B 세트(동작 단어가 깨진 입력)를 어떻게 학습시킬지 선택지가 두 가지입니다.

### 방법 1: 정답 호출을 그대로 붙인다 (이번에 한 방법)

`에어컨 그 주소.` → `<six_0>(object=2, type=2)<six_end>` (에어컨 끄기)

모델이 "에어컨 + 깨진 동작"을 보면 끄기일 가능성이 높다고 **추측해서 실행**하도록 배웁니다. 맞으면 바로 동작하지만, 틀리면 엉뚱한 동작이 실행됩니다.

### 방법 2: 되묻기로 바꾼다

추측하지 않고 "무엇을 하려는 건가요?"라고 다시 물어보게 하는 방법입니다. 안전하지만 **현재 형식으로는 표현할 수 없습니다.**

- 지금의 되묻기는 `<six_0>(object=-1)<six_end>`이고, `object=-1`은 **"어떤 기기인지 모르겠다"**는 뜻입니다. 예: "그것 좀 꺼줘"처럼 기기가 없는 말.
- B 세트는 반대 상황입니다. **기기는 에어컨으로 알겠는데, 동작(켜기/끄기)을 모르겠는** 경우입니다.
- 이걸 `object=-1`로 학습시키면 앱이 "어떤 기기요?"라고 물어보게 되어 실제 상황과 맞지 않습니다.

방법 2를 쓰려면 새로 정해야 할 것:
1. **형식:** 예를 들면 `<six_0>(object=2, type=-1)<six_end>`처럼 "기기는 에어컨, 동작은 모름"을 나타내는 호출을 새로 정의
2. **앱의 동작:** 그 호출을 받으면 "에어컨을 켤까요, 끌까요?"라고 되묻도록 파서 · 대시보드 · TTS를 수정

LLM뿐 아니라 파서와 앱을 만드는 팀원도 같이 정해야 해서 팀 합의가 필요합니다.

### 비교

| | 방법 1 (정답 그대로) | 방법 2 (동작 되묻기) |
|---|---|---|
| 맞는 경우 | 바로 실행 | 한 번 더 물어봄 (불편) |
| 틀리는 경우 | 반대 동작이 실행됨 (위험) | 물어봄 (안전) |
| 필요한 작업 | 없음 (이미 완료) | 형식 정의, 파서·앱 수정, 재학습 |
| 실제 녹음 결과 | 87.4% → 94.7% | 해 보지 않음 |

**현재 판단:** 시연이 가까우면 방법 1을 유지하되, 켜기↔끄기 뒤집힘이 2개 남아 있다는 한계를 알고 가는 것이 현실적입니다. 방법 2는 서비스로 이어갈 때 더 안전한 설계이므로 향후 개선 과제로 논의할 만합니다.
